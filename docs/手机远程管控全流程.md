# 手机远程管控 · nas-push-stack 侧的联动部分

> **这一块已经拆成独立项目**：[`ksoulness/iphone-esim-control`](https://github.com/ksoulness/iphone-esim-control)
> 装控制端、把手机交给脚本/AI、在手机上写捷径与自动化、切卡实战、加卡 SOP、排障——全部在那里，本仓库不再重复。
>
> 本文只保留**本仓库需要负责的那一半**：队列与状态 API、2999 页面、iMessage 门铃、飞书结果通知、验证码回传。两边只通过下面这几个接口粘在一起，任何一边换实现都不影响另一边。

## 0. 分工边界

| 层 | 归谁 | 内容 |
| --- | --- | --- |
| 控制层 | 独立项目 | 一台常开 Mac/Linux + USB 连着的 iPhone，用 `iphone-control`（iOS 27 原生控制，免签名）读屏、点按、打字，必要时在手机上建/改捷径 |
| 手机端 | 独立项目 | 捷径 `切换cte / 切换hk / 切换dito / 切换giff`（关其它三条 + 打开目标 + 回报）、`查询当前卡`，以及 `#phone on …` / `#phone status` 触发器自动化 |
| 服务层 | **本仓库** | 指令队列（`/phone/cmd`、`/phone/state`、`/phone/plans`）、手机侧入口（`/p/<token>/phone/…`）、2999 `/phone` 页面、iMessage 门铃、飞书结果、看门狗、验证码存储与推送 |

**两个联动点（唯一契约）**

1. **门铃（本仓库 → 手机）**：入队后本仓库发一条 iMessage，正文严格是
   ```
   #phone on <卡名>        # 切到某张卡（等价 default）
   #phone off <卡名>       # 关掉某张卡
   #phone status           # 让手机回报当前活跃线路
   ```
   实现：`POST <NAS>/notify/imessage_nas`（apprise 的 `imessage_nas` 通道，NAS 直发 iMessage，走 8098 网关）。
2. **结果（手机 → 本仓库）**：手机捷径回打
   ```
   GET /p/<token>/phone/report?ok=1&detail=<卡名>&act=default&plan=<卡名>
   GET /p/<token>/phone/report?ok=1&act=status&detail=CTE,US
   ```
   本仓库据此落 `state=done/failed`、更新 `last` / `active`，然后推飞书。

## 1. 服务端接口（本仓库实现）

| 端点 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /phone/state` | 内网免，公网需 `ctl` | 返回 `plans` / `queue` / `history` / `last` / `active` |
| `GET /phone/cmd?action=default\|toggle\|status&plan=…&on=…` | `ctl` | 入队并立刻发门铃 |
| `GET /phone/plans?data=<urlenc JSON>` | `ctl` | 整体替换线路清单（`name/alias/number/role`，`role` = `switch`/`always_on`/`data_only`） |
| `GET /p/<token>/phone/pull?fmt=text&act=on\|off\|default\|status` | token | 手机侧拉取（纯文本 `action\|plan\|on\|id\|role`，空为 `noop\|\|\|\|`） |
| `GET /p/<token>/phone/report?…` | token | 手机侧回报；不带 `id` 时按 `act`/`plan` 匹配最老 `pending\|taken`，再退化为按 `plan` 匹配 |
| `GET /p/<token>/phone/otp?code=…&from=…` | token | 验证码写入并推飞书（**不在页面展示**，只走飞书） |

要点：
- **`ctl` 口令免验条件**是「来自内网/本机」——页面通过反代访问所以不用带口令，公网无口令一律 403。
- **主队列可以只在云主机**：页面侧（NAS）通过 `PHONE_MASTER` 把 `/phone/*` 转发过去；转发失败时**回退读本机状态**而不是报 502，页面才不会整块空白。
- **看门狗**：`taken` 超过 150 秒没有 `report` → 置 `failed` 并推飞书「手机 150 秒内没有回报」。

## 2. 2999 页面（`/phone` 标签）

只保留两种东西，**没有「开启/关闭」**：

- 顶部：`刷新` + `向手机查询当前线路`（入队 `action=status`）+ `当前挂卡：US + CTE`；
- 每张可切换卡：一个「换成这张」（当前那张显示 `● 当前` / 「就是这张，不用再切」并高亮绿边）；
- 常开卡与纯流量卡只在底部灰字列出；
- 旧「线路清单 / 待执行指令 / 最近结果」收进 `<details>` 折叠区；
- **验证码不在页面展示**（用户只在飞书看，减少暴露面）。

踩过的两个页面级坑（换实现时别重犯）：
1. 每个 `pane-x` 都必须带 `style="display:none"`，且 `tab()` 必须**无条件调用一次**——否则 iframe 不带 hash 时多个 pane 会叠在一起，表现为「所有标签看起来一模一样」；
2. 号码切换块属于 `pane-p`（`/phone`），不要写在 `pane-n`（`/numbers`），否则会在号码页出现。

## 3. 结果通知（飞书「短信」群）

```
✅ 切换成功｜iPhone：卡1 固定 US；卡2 由 HK 切到 **CTE**（手机已执行）
❌ 切换失败｜iPhone：卡2 仍停在 HK，切 PH 没成功（所选蜂窝号码当前未激活）
📶 线路状态｜iPhone：卡1 固定 US；卡2 当前 CTE
🔑 验证码｜<来源> <code>
```

实现：`POST https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id`，凭证在 `feishu.env`（`FEISHU_APP_ID/SECRET` + 群 `chat_id`），通道名走 `FEISHU_CHAT_ROUTES` 里的 `smsgrp`。
`last` / `active` 落盘在 `phone-state.json`，重启不丢。

写入时机：`last` 在「切卡成功 / toggle 开启成功」时写，**`act=status` 回报时也会反推**（挑回报里那张非 `always_on` / `data_only` 的卡写回，变名打日志 `[phone] status sync phone_last: A -> B`；只有常开卡活跃时保持原值）。这样用户在手机「设置 → 蜂窝网络」里手动切了卡，页面点一次「向手机查询当前线路」就能把高亮纠正过来。

## 4. 与通知转发的联动

同一个 iMessage 网关同时干两件事：**把 iPhone 的通知转发出去**（`/p/<token>/ios2and`，见 [iOS 通知转发](iOS通知转发-最终形态与NAS侧过滤.md)）和**把队列指令叫醒手机**（本节的门铃）。两条路互不影响。

切卡成功后哪张卡收短信，取决于运营商的线路设置；本项目刻意**不设默认线路**（只用「同时激活 2 条」的规则），所以两条卡的短信都会到手机上，转发捷径都能收到。
